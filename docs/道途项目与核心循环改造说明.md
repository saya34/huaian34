# 《槐安一梦》道途项目与核心循环改造说明

> 对应版本：`b2d8674`
>
> 变更主题：首个道途项目、六阶段游戏时钟、基础经济防套利、项目结果的世界反馈
>
> 文档口径：只记录本次已经落地的逻辑；尚未实现的设计单独列在文末。

## 1. 改造目标

本轮不增加新的独立玩法，而是在现有恋爱、农田、炼丹、战斗、商店等系统之上增加一个明确的中期目标，让玩家知道当前为什么准备、准备什么，以及不同玩法怎样共同影响同一个结果。

首个验证项目为 **「坊市药材断供」**。它承担四项验证任务：

1. 玩家能否立即理解危机目标和剩余时间。
2. 玩家能否从生产、关系和战斗中选择一条主解法，而不是被迫清空所有玩法。
3. 玩家能否理解“库存”与“亲自完成的劳动”是两种不同的条件。
4. 项目完成后，玩家能否在场景、NPC 和商店中看到自己的选择造成的结果。

## 2. 核心流程

```text
主界面发现道途项目
        ↓
接取「坊市药材断供」并开启三日危机窗口
        ↓
从生产 / 关系 / 战斗中选择一条主路线
        ↓
完成所选路线的可见准备条件
        ↓
交付物资并结算
        ↓
医馆恢复、商店补给改善、柳知意日程改变
```

路线可以随时重新选择，玩家只需完成最终选定的一条路线。其他系统不会成为隐藏的强制条件。

## 3. 道途项目状态模型

本次在恋爱主状态中增加 `medicineShortage`：

```ts
type MedicineShortageProject = {
  status: "offered" | "active" | "completed";
  acceptedDay?: number;
  deadlineDay?: number;
  route?: "production" | "relationship" | "battle";
  battleVictories: number;
  farmHarvestsAtAccept?: number;
  completedDay?: number;
  outcome?: "stabilized" | "recovered";
};
```

各状态含义：

- `offered`：项目已经出现，但玩家尚未接取，不计时。
- `active`：项目进行中，记录接取日、危机截止日、主路线和路线进度。
- `completed`：项目已结算，记录完成日期和结果等级。
- `stabilized`：在三日危机窗口内完成，获得完整奖励。
- `recovered`：超过危机窗口后完成，进入补救结算，不会永久错过剧情。

接取时执行：

```text
acceptedDay = 当前游戏日
deadlineDay = 当前游戏日 + 2
battleVictories = 0
farmHarvestsAtAccept = 当前累计收获次数
```

`deadlineDay` 采用包含首尾的计算方式，因此玩家从接取日起拥有三个游戏日。

## 4. 三条主解法

### 4.1 生产路线：灵田 → 丹炉

交付条件：

- 接取项目后亲手完成至少一次农田收获。
- 持有 3 份「碧落灵芝」。
- 持有 1 枚「碧落回春丹」。

“亲自收获”通过比较当前 `farm.totalHarvests` 与接取时保存的 `farmHarvestsAtAccept` 判断。这样即使玩家可以在市场买到灵芝，也不能只靠采购完成生产路线；至少要留下真实的种植劳动记录。

交付时消耗 3 份碧落灵芝和 1 枚碧落回春丹。

### 4.2 关系路线：药师协作

交付条件：

- 柳知意缘分达到 12。
- 持有 2 份「霜心草」。

关系值代表玩家已经完成社交投入和人物推进，因此关系本身就是不可直接采购的劳动证明。交付时消耗 2 份霜心草。

### 4.3 战斗路线：秘境夺材

交付条件：

- 接取项目后至少完成一次秘境胜利。
- 行囊内保留至少一份来源标签包含 `battle` 的秘境灵材。

秘境胜利只在项目处于 `active` 时计入 `battleVictories`。交付时消耗一份符合条件的秘境灵材。

## 5. 里程碑与界面反馈

道途项目界面固定展示五个里程碑：

1. 接下医馆告急。
2. 确定一条主解法。
3. 完成物资与风险准备。
4. 交付替代药材。
5. 见证坊市恢复。

主场景增加常驻的道途追踪器，展示：

- 项目是否待接取、进行中或已完成。
- 当前项目名称。
- 危机期剩余游戏日。
- 逾期后的补救提示。
- 完成后的世界变化入口。

项目窗口采用古风事件卷宗式布局，路线以三张可选择的方案卡呈现，不使用表格。完成后播放扩散光环动效，并把医馆、商店和人物日程三项变化分别列出。

手机端将三条路线改为横向滑动卡片，里程碑改为紧凑的横向进度条，交付区固定在可操作位置。

## 6. 项目结算

危机期内完成：

- 灵石 `+240`。
- 柳知意缘分 `+3`。
- 获得锁定剧情物品「医馆回春契」。
- 设置世界标记 `medicine_supply_restored = true`。
- 结果记录为 `stabilized`。

逾期补救完成：

- 灵石 `+100`。
- 柳知意缘分 `+1`。
- 同样获得「医馆回春契」。
- 同样恢复医馆和后续世界状态。
- 结果记录为 `recovered`。

逾期只降低收益，不会删除项目、封锁剧情或让新手永久错过内容。

## 7. 可见的世界变化

完成项目后，世界标记会同时写入共享状态与恋爱模块状态，供不同玩法读取。

### 7.1 医馆状态

主场景出现「医馆药路重开」状态提示，明确告诉玩家项目结果已经进入世界状态，而不是只在结算弹窗里显示一次。

### 7.2 商店状态

栖珍阁显示「供给恢复」横幅，并对百宝柜基础商品提供额外价格减免。

折扣逻辑为：

```text
最终折扣 = max(0.78, 人物缘分折扣 × 0.92)
```

即供给恢复会带来约 8% 的额外减免，同时设置 78 折下限，避免多个优惠无限叠加。

### 7.3 柳知意日程

世界标记生效后，柳知意会在其所属场景的清晨、上午和午后稳定出现，表现她从外出寻药恢复为白天坐诊。

## 8. 六阶段游戏时钟

一天统一划分为：

```text
清晨 → 上午 → 午后 → 黄昏 → 夜晚 → 深夜 → 次日清晨
```

原先的三阶段逻辑已经扩展为六阶段。新增状态：

```ts
shortRestDay: number;
shortRestCount: number;
```

用于记录当天已经短休的次数，并在进入新的一天时清零。

### 8.1 等待

- 推进一个游戏阶段。
- 不恢复体力。
- 深夜等待后进入次日清晨。

### 8.2 短休

- 推进一个游戏阶段。
- 第一次恢复 3 点体力。
- 第二次恢复 2 点体力。
- 第三次及以后每次恢复 1 点体力。
- 体力上限仍为 10。
- 新的一天会重置短休次数。

### 8.3 睡眠

- 直接结束当天。
- 进入次日清晨。
- 恢复至 10 点体力。
- 不额外赠送材料或货币。

### 8.4 社交行动

- 普通交谈推进一个游戏阶段，不消耗体力。
- 赠礼推进一个游戏阶段并消耗礼物，不消耗体力。

这使社交的主要成本变成日程机会，而不是与采矿、战斗争抢同一种体力成本。

### 8.5 战斗行动

副本结算后：

- 游戏时间推进一个阶段。
- 消耗 3 点体力。
- 胜利时更新副本进度。
- 若药材断供项目正在进行，胜利额外计入战斗路线进度。

## 9. 六阶段与生产系统同步

以下系统的游戏 Tick 已统一为：

```ts
tick = (day - 1) * 6 + 当前阶段索引;
```

已同步的系统：

- 农田作物生长。
- 畜牧生产、照料与完成时间。
- 钓鱼陈化时间。
- 炼丹市场与委托刷新。

旧人物配置仍有只声明「清晨、黄昏、夜晚」的规则。为保证六阶段迁移后角色不会在新增阶段集体消失，增加了兼容映射：

```text
上午兼容清晨规则
午后兼容黄昏规则
深夜兼容夜晚规则
```

后续可逐个角色改成独立六阶段日程；兼容映射只是存量内容迁移层。

## 10. 市场与委托改造

### 10.1 移除现实倒计时驱动

集市刷新、售罄补货和委托换榜不再使用 `Date.now()` 或浏览器定时器推进，而是读取统一游戏 Tick。

当前规则：

- 手动免费刷新恢复：6 个游戏阶段。
- 委托榜刷新：6 个游戏阶段。
- 全场售罄补货：1 个游戏阶段。
- 玩家关闭页面或离线不会让这些世界状态自行跨日推进。

旧存档中保存的毫秒时间戳通常大于 `1,000,000`。载入炼丹界面时会把这类旧值识别为遗留现实时间并归零，避免迁移后出现极长等待。

### 10.2 防止纯采购套利

指定材料委托的奖励倍率从市场估值的 `1.45` 调整为 `0.8`：

```text
材料救急回收 = 市场参考价 × 数量 × 0.8
```

因此“市场购买材料 → 原样交委托”不再稳定获利。材料委托被明确标记为救急档回收；炼制成品、品质条件和模糊丹药委托继续承担完整劳动奖励。

委托界面同步增加说明：纯采购只按救急价回收，炼制、品质与调查型劳动才提供完整收益。

## 11. 存档兼容

本次没有提升统一存档版本号，而是通过默认状态合并兼容旧存档：

- 旧存档没有 `medicineShortage` 时，使用默认 `offered` 状态。
- 旧存档没有短休字段时，使用当天 0 次短休。
- 炼丹模块旧的现实时间戳会在读取时迁移为新的游戏 Tick 逻辑。
- 畜牧旧数据仍保留原字段，并为缺失的 Tick 字段补默认值。

玩家不需要重开存档即可看到新的道途项目。
