# 核心大组件职责拆分与战斗边界清单

> 目标：不改变当前玩家体验，只降低继续开发时的状态漂移、结算重复和副作用泄漏风险。

## 世界模块

- [x] 将远端/内置世界内容合并与加载拆入 `useWorldContent`。
- [x] 将场景、人物、医馆状态等可推导值拆入纯 selector。
- [x] 将切场景的业务顺序固化为：写入目的地 → 自动世界键 → 人物在场判定 → 当前人物 → 强制事件 → 普通事件。
- [x] 将推进时辰的业务顺序固化为：时间与体力 → 自动世界键 → 人物在场判定 → 强制事件 → 主动相遇 → 普通事件。
- [x] 世界运行状态只由 `UnifiedGameProvider.state.romance` 提供；视图不保存其副本。
- [x] 全局 HUD 使用独立 `WorldHud`。
- [x] 地图、任务、人物谱、活动与系统面板保持独立组件边界。
- [x] 剧情/事件的规则继续由事件引擎执行，世界页面只负责选择入口与渲染结果。
- [x] 初始化、读档、迁移和持久化不再放在世界展示组件内。

## 统一状态与存档

- [x] `UnifiedGameProvider` 缩减为上下文、持久化协调和公开写入口。
- [x] 存档清洗与版本兼容拆入 `save-migration.ts`。
- [x] 货币、物品、成长、关系、任务、秘境等效果归一到 `game-state-reducer.ts`。
- [x] 所有可推导投影由 reducer/selector 生成，不在组件内另存同义状态。
- [x] 浏览器存储读取失败仍回落到可启动的初始状态。

## 战斗模块

- [x] Canvas 引擎只负责实时战斗模拟和快照，不直接写存档或任务状态。
- [x] React 层通过 `resolveBattleSettlement` 将战斗快照一次性转换为统一效果。
- [x] 战斗开始时通过 `lockBattleSession` 深拷贝关卡、配装、补给和成长配置。
- [x] 运行中的战斗不再响应其他页面对永久属性/配装的修改。
- [x] 每次战斗使用唯一 session id，胜利、撤离或失败回调只能提交一次。
- [x] 引擎自身还有 `ended` 门，避免同一帧重复触发结束回调。
- [x] 卸载时释放 RAF、ResizeObserver、键盘监听、窗口 resize 监听和摇杆输入。
- [x] React 层释放阶段计时器、提示计时器、伙伴/揭示计时器并销毁引擎。
- [x] 胜利：带出背包和保险格、带出可容纳装备、发放经验/残卷、推进关卡与任务。
- [x] 撤离：带出背包和保险格、带出可容纳装备、不发关卡经验、不推进关卡完成记录、承担行动成本。
- [x] 失败：仅保留保险格、不带出临时装备、不发关卡经验、不推进关卡和任务、不重复扣行动成本。

## 大组件拆分结果

- [x] `AlchemyGame.tsx`：NPC、结果揭示、市场、模糊委托选择、图鉴、太初命卷创建、神话卡揭晓和人物卡名册均已拆成展示组件。

- [x] TypeScript 全量类型检查。

- [x] 现有剧情、任务和功法数据检查。

## 维护约束

1. 新业务效果优先新增 `GameEffect`，并只在统一 reducer 中落地。
2. 新世界规则优先写成纯 selector/transition，不要写入 JSX 展示组件。
3. 新战斗奖励必须进入 settlement service，不得在 Canvas 回调中直接操作 localStorage。
4. 任何新增 RAF、定时器、Observer 或事件监听都必须在同一职责模块中提供清理路径。
5. 修改胜利、撤离、失败规则时同步更新 `check:architecture` 的策略校验。
