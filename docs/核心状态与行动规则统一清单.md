# 核心状态与行动规则统一清单

更新时间：2026-09-13

## 实现结果

- ✅ 玩家经验只保留一套权威成长状态
  - `shared.playerLevel` 与 `shared.playerExperience` 是唯一权威值。
  - 任务、剧情、练功与战斗结算统一经过成长服务；服务负责升级、阈值扣除与剩余经验。
  - 每次更新都会投影到恋爱主世界与战斗存档，读取旧存档时也会重新归一化。
  - 钓鱼、采矿、农田等采集职业经验继续保存在采集职业系统中，不与角色修为混用。

- ✅ 主世界、战前整备与战斗共用最终属性服务
  - 统一计算顺序为：基础属性 → 根基分配 → 功法被动 → 法器 → 被动命格 → 临时丹药 → 关卡修正。
  - 主世界人物属性、战前战力、装备换装对比和战斗引擎均读取同一计算结果。
  - 被动命格不再同时从旧战斗卡库和共享卡库重复叠加。

- ✅ 炼丹成品并入通用物品实例库存
  - 每个丹药实例记录基础模板、数量、品质、异变、来源和展示名称。
  - 异变丹药使用稳定实例编号，行囊、炼丹委托和战前补给操作同一份数量。
  - 旧的炼丹基础物品投影会在读档时迁移，避免基础丹药与异变丹药重复显示或重复消耗。

- ✅ 物品条件统一校验类型、稀有度与数量
  - 新增统一物品查询服务，支持 `itemType`、`templateId`、最低稀有度和最低数量组合条件。
  - 剧情事件、任务目标和炼丹委托库存显示共用该查询口径。
  - 高稀有度礼物不再错误满足高品质丹药条件。

- ✅ 命格卡以唯一 ID 贯穿库存、展廊、卡槽与战斗召唤
  - 战斗内卡片展廊直接读取共享命格元数据，不再依赖另一份旧卡库，因此不会出现“有数量但展廊为空”。
  - 卡槽保存唯一卡片 ID；召唤时人物名称、招式名与立绘直接取自所选卡片。
  - “沈清霜·霜华一剑”不再映射为“凌霜师姐·万剑归宗”。
  - 卡片名称统一清洗相邻重复词，重复 ID 使用更新而非重复追加。

- ✅ 行动成本采用统一配置、准入检查和单次扣除规则
  - 秘境、炼丹、练功、农田照料、等待、短休和睡眠成本集中配置。
  - 战前页与行动入口在确认前展示成本；体力不足时拒绝开始。
  - 炼丹会先完成材料及词条校验，再扣除一次成本。
  - 战斗只在胜利或主动撤离结算时扣除成本；初始化失败或战败不扣体力、不推进时辰。

## 验证记录

- ✅ 生产构建：`pnpm run build`
- ✅ 成长阈值与物品类型/稀有度查询冒烟测试
- ✅ 本地首页：`http://localhost:3000/` 返回 HTTP 200
- ✅ 本轮没有无法实现项

## 关键公共模块

- `app/game/core/progression-service.ts`：角色等级与经验唯一结算入口。
- `app/game/core/attributes-service.ts`：最终战斗属性唯一计算入口。
- `app/game/core/item-query.ts`：任务、事件和委托共用的库存条件查询。
- `app/game/core/inventory-service.ts`：物品实例投影及炼丹成品同步。
- `app/game/core/card-service.ts`：命格元数据归一化和唯一 ID 更新。
- `app/game/core/action-service.ts`：行动成本配置读取、展示与准入判断。
- `app/game/core/content/actions.json`：行动成本文本与数值素材。
